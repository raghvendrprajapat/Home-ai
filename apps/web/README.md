# GharPlan web and Android application — PH1-T04

Run commands from the repository root, using Node 24.19.0 and pnpm 11.19.0:

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm dev
```

The development server uses port 5173 with strict port selection. The sample plan is now editable: drag a corner, enter precise X/Y coordinates, fit/pan/zoom the drawing, toggle its grid and undo/redo. Area labels use the geometry engine's clear inside area. Connected orthogonal groups move together; invalid commands reject atomically. Touch handles have larger picking targets, and a second finger cancels an edit until both fingers lift.

Switch to **3D view** for real wall openings, clear-area floors, door thresholds and dimensioned furniture placeholders. Drag to orbit, use two fingers to pan/zoom, or focus the canvas and use arrow keys / + / −. The precision controls and undo/redo update both views from the same core-model. Only changed mesh buffers/GPU geometries rebuild; outdated worker results are rejected. Context loss, worker startup and engine-load failures preserve the live model and offer 2D continuation.

The editable drawing now autosaves to transactional IndexedDB. Android additionally mirrors validated full copies through the private native Filesystem plugin. The save label acknowledges the current document only after the required writes finish; a failed or stalled phone backup warns while browser autosave continues. Reload with newer journal entries offers recovery before editing. Conflicts retain exportable in-memory changes; damaged or unsupported originals stay untouched, and repaired drawings/native backups open as separate copies with new IDs. Undo history is session-only; recovered content starts a new editor session.

**Export drawing** downloads complete JSON in a normal browser. Android offers a system Save-file picker using a private cache source; success requires exact byte/hash readback from the chosen provider. Cancel/failure preserves selectable JSON and guarded copy. Clipboard success alone is not file-save acknowledgement. This is a click-time snapshot; later edits need another export. The native picker stores only small path/hash/length metadata while Android backgrounds the app; a dedicated I/O thread keeps provider stalls away from the bridge/autosave queue. A stalled provider cannot be universally cancelled; JSON remains available. A partial destination can remain after failure, and abandoned temporary cache sources have bounded admission. Physical provider/picker execution is still unverified. Keep independent backups: clearing application data or uninstalling can remove both local stores. The project list now creates independent blank drawings, opens, renames, duplicates and reversibly trashes/restores local drawings. A blank drawing can add one starter room through the tested model command. Projects also imports plain UTF-8 JSON up to 10 MiB. Preview/cancel is read-only; newer/malformed/unknown/fractional data rejects unchanged. Original IDs/content are kept if absent; existing/trashed/native-history/unknown IDs require a separate copy and never overwrite original files. Read/worker watchdogs preserve the current drawing; parsing is off-thread. Exact import and new-copy initialization stay no-overwrite under races. Full drawing tools, accounts and the asset catalog remain pending. Android compilation, signature/manifest/config/assets and native plugin packaging are verified; phone execution/durability remain pending. See [`../../docs/verification/ph0-t08.md`](../../docs/verification/ph0-t08.md) and the [phone recovery procedure](../../docs/benchmarks/local-recovery.md). The editor, project list, welcome, recovery and settings support English/Hindi; language changes preserve drawing names/data. Settings remember language and new-drawing unit preference best-effort. Imperial area labels still use integer-mm canonical geometry; precision inputs currently remain mm. Projects/Settings are UI-only routes; no app document is stored in Zustand or preference storage. Switching drawings waits for a completed primary local save and refuses to discard unsaved/error/conflict memory. Local trash has no automatic expiry and preserves both browser and native data. Database v2 preserves v1 rows and blocks stale v1 app writers. Real Hindi phone layouts remain pending. Konva/Three own dedicated inner canvas containers; React owns controls and overlays. Renderer state is never project data. Three.js is loaded only when 3D is selected.
