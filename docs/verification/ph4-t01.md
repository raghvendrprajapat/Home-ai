## Limits and owner protocol

The pilot comprises six individually closed original boxes; it is not a welded manufacturing solid or photorealistic furniture. LOD0/1share one72triangle GLB because it meets both budgets; no simplification/compression claim. PreviewSVG is stylized. Arbitrary imports/textures are deliberately rejected. Rights records preserve owner rights, make noCC0/exclusive-copyrightability assertion and are not independent legal clearance. Catalog UI/asset placement and the~30item catalog remain later tasks. No schema, accepted independent fixture or preserved untracked owner-file edit; D39 records the one-axis clarification in the tracked spec.

Build publication assumes a single writer and ordinary sibling renames, not fsync/process-death/concurrent-writer durability. A stopped build can leave its own tempfiles/unreferencednewblobs; checks report them for inspection without deleting unknown files. New generator/vendor formats must preserve old approved artifacts/version contracts; the Git guard blocks silent regeneration under an existingversion. No physicalLow/Mid/provider/OEM/thermal/Hindi/TalkBack/browsermatrix acceptance is claimed. Cached native helpers are not fresh Android execution.

D36 permission is required before any cloud/account/sync/history, mobileoptimization/directshare/realphones, billing/subscription/security/privacy/release/finalClaude. These scopes remain unstarted. Prospective steps below do not authorize execution:

2. Verify existing editor2D/3D,Undo/reload and file export still work; this PR adds no catalog screen, so do not expect an AddDesk button yet.
3. Record build/device/WebView details and errors. Catalog usability/loading and phone asset budgets receive their protocol after that UI exists and the owner permits device testing.
