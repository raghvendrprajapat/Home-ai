## Behaviour and architecture

The sample is drawn from the subscribed immutable core-model snapshot: shared wall footprints, clear room polygons/areas, opening marks, dimensioned furniture footprints and corner handles. Konva is display-only and owns a dedicated empty inner element; React owns controls and overlays. A room label remains readable above furniture; tiny spaces also retain their DOM warning/area row.

Corner drag tracks original corner and pointer delta, avoiding a jump when the hit target is grabbed off-centre. X changes propagate through vertical-linked junctions; Y changes propagate through horizontal-linked junctions. The complete candidate goes through the same core-model command validation. Preview uses an isolated candidate store and changes neither the live document nor history; release creates one transaction. Invalid/rejected edits leave the live snapshot unchanged. Escape, owner pointer cancellation/capture loss, viewport fit/resize and generation changes discard previews. Wheel zoom is handled by a non-passive listener and prevents unwanted page scroll. Two-finger input cancels editing and suppresses another edit until all fingers lift; pinch navigation remains a later task.

The viewport has invertible plan/screen transformations, anchored bounded zoom, fit and empty-space pan. Existing-junction snapping uses 12 CSS px acquire, 1.5× hysteresis, a 250 mm world cap and stable ID ties. Shift bypasses snapping; raw input quantizes once to integer mm. Wall-centreline/alignment/grid snapping and full drawing tools remain PH2 work. Konva transforms are never serialized.

DOM controls offer selected-corner selection, integer X/Y editing, fit/grid, undo/redo and room areas; Ctrl/Cmd+Z, Shift+Z and Ctrl+Y work outside text inputs. In-memory-only status and reload behaviour are explicit. No save/cloud claim is made.
