## Implemented contract

`packages/core-model` owns the single project document and derives geometry from it. It has no DOM, React, renderer or network imports. `ProjectStore.getSnapshot`/`subscribe` provide immutable stable snapshots for future view adapters. Public patches and inverse patches are deeply frozen so adapters cannot corrupt private history.

The authoritative Draft202012 schema is compiled to a checked-in standalone validator. `pnpm schema:check` regenerates and byte-compares it on every CI run. Production validation needs no `eval`, `new Function` or runtime schema compilation. Ajv's generated literal CommonJS helper references are mechanically converted to ESM imports, with function/default helper interoperability tested through actual schema loads.

`validateProject` additionally checks globally unique IDs, safe revision counters, one floor, geometry/material/floor references, exact positive room boundaries, integer furniture/light coordinates, canonical size/finite-number limits, opening hosts/end clearances/height and overlap. Loading rejects unsupported versions and fractional saved coordinates; these are never treated as pointer inputs. Serialization sorts object keys and retains entity array order, pinned asset versions and exact mm values. A 10 MiB UTF-8 document limit applies. The dependency hash is a cache tag, not a cryptographic hash or server receipt.

Commands implement wall/rectangle creation, junction/wall movement, wall reversal/deletion/properties, opening and furniture CRUD, room properties, project naming and units. Normalization, room assignment, opening lineage/rehosting and validation occur inside one Immer candidate transaction. Rejection leaves the authoritative snapshot, history, generation and listeners untouched. An exact duplicate wall remains a no-op. Generated room and split-wall IDs reserve every entity namespace, including furniture/materials. A split through an opening rejects; wall reversal maps the opening centre to `L − offset` and toggles `flipX`.

Opening edits invalidate host meshes. Wall geometry edits invalidate changed footprint owners and conservatively nearby owners across height bands; a 500 mm centreline expansion bounds the maximum allowed half-thickness/cap. This covers tall neighbour caps whose changes are masked at ground level by a short wide wall. Untouched furniture edits retain wall identity. The incremental renderer must use generation/dependency stamps as well as entity revisions: undo restores old entity revisions, so a subsequent different edit can reuse a revision value.

Local generation increases on each successful edit/undo/redo and never rewinds. Server revision changes only through a matching safe-integer acknowledgement. Existing undo patches do not include acknowledgements, so undo retains the last confirmed server revision. Async result tags check project ID, session ID, generation and dependency hash. Actual cloud authentication/save-conflict enforcement is a later task.

History has a 20 MiB patch/inverse budget. Normal-size 100-step undo is tested; older entries are evicted when the byte budget is exceeded and `historyTruncated` exposes that fact. One oversized entry is rejected before commit. Listeners run after commit; listener exceptions, including broken diagnostic getters, are recorded without changing a successful result. Reentrant commands/history/acknowledgements during notification reject, preventing reordered journal notifications.
