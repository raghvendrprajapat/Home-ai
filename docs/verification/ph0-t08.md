## Behavior and design

Accepted core commands, undo, redo and server-confirmed revision changes emit immutable actual Immer patches before general UI subscriptions. Renderers still never write project data. Runtime generation, server revision and local disk sequence remain separate. The sample server revision is 1; local edits do not invent a newer server revision.

`packages/persistence` stores one versioned metadata/head row, compressed or raw validated checkpoints and forward journal events in IndexedDB. A commit compares the complete previous `{projectId, epoch, seq, hash}` and atomically updates journal/checkpoints/meta in one strict-durability transaction. Hashing/compression finish before opening that transaction. Acknowledgment waits for `transaction.oncomplete`; injected synchronous failure aborts every put. Another tab's newer head produces a conflict, retains exportable memory and never silently overwrites the winner on retry.

Edits schedule a 250 ms coalesced attempt. Checkpoints occur every 50 events or 30 seconds of activity, retaining the newest and previous checkpoint plus journals needed from the older one. Sequence numbers never reuse runtime undo generations. SHA-256 binds exact serialized bytes and contiguous journal links; it is corruption detection, not cryptographic authentication.

Android additionally writes immutable complete JSON through `@capacitor/filesystem` 8.1.4 in private `Directory.Data`. Temporary document and ready-marker writes/renames each receive bounded readback verification. A candidate opens only after marker, checksum, identity, schema and geometry validation. The inspected native implementation does not establish atomic rename across its fallback or fsync/power-loss guarantees. Keeping the previous validated copy and validating markers helps recovery without pretending to prove those semantics.

Browser and native writers run independently. A delayed native acknowledgment refers to its actual full head, including sequence; an undo returning to identical bytes does not make an old backup current. After a 1500 ms diagnostic timeout, the app warns and continues browser journals. The timeout does not cancel native I/O or promise a fixed save latency. A later acknowledgment coalesces the latest head. Android shows **Saved on this phone** only when both required stores match the current document; partial/error/conflict states offer export and retry. Browser completion says saved in this browser, not cloud.

Startup validates checkpoints and replays only contiguous valid journal entries before editing. A newer journal, fallback damage, native divergence or inspection warning shows recovery choices. Cancel leaves saved files untouched. Semantic room-boundary repair is proposed only when all other schema/reference/geometry checks pass; it is explicit, preserves originals and opens a new-ID copy. Partial replay and native backups also open new-ID copies. Future/unsupported/invalid/fractional data cannot be silently normalized into canonical projects. IDB-corrupt bytes/meta remain available for support.

Native scans are bounded (1000 directories, 600 names per directory, 10 MiB documents, 2048-byte markers). One unreadable/oversized/damaged directory does not hide other valid backups. Epochs are never ordered by timestamp; equal-sequence differing hashes remain explicit candidates. Unsupported or aliased markers prevent pruning that folder, including referenced originals. Unknown/orphan files are not guessed away. A separately recovered drawing can create its own backup without replacing the damaged source folder.

Web export downloads complete versioned JSON; Android currently offers complete JSON and a guarded copy action. Native file download/share, full import, project list and accounts are future tasks. Undo stacks are session-only. `/perf` remains disposable and never opens or autosaves the user's drawing.

## Replay and remaining gates

From the repository root, run `pnpm check`, `pnpm android:sync`, then the scoped verified-toolchain Gradle command in [phase0.md](../benchmarks/phase0.md). Run the production server with `pnpm android:benchmark-web`. With Python jsonschema/Playwright and Chromium installed, run:

```sh
python docs/verification/scripts/ph0-t08-browser.py
python docs/verification/scripts/ph0-t08-crash.py
```

These use private test browser contexts/profiles. The crash script launches a new session/process group and kills only that owned Chromium group. Its during-write test uses a test-only binding and a 300 ms handler stall; it accepts old or new atomic state and checks actual persisted metadata/journal/geometry after restart. It is not Android power-loss evidence.

Follow [the Low/Mid phone recovery procedure](../benchmarks/local-recovery.md). Physical 100-cycle recovery, ≤2 s lost edits, p95 ≤500 ms journal writes, WebView-only eviction, true device-full/private mode, OEM backup/transfer, native fsync/power-loss and storage-clear behavior remain **Pending**. A complete `pm clear` or uninstall removes both application stores; offline code cannot distinguish an entirely cleared installation from first launch without external evidence. Import/cloud restore UI and independent backup guidance are necessary; never promise the mirror survives application-data clearing.
