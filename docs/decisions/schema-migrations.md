# PH1-T02 — schema admission and migration framework

D23, 2026-10-12, under D17. Production remains schema **1**, matching the accepted JSON Schema, TypeScript document and generated validator. Version 1 is the first documented GharPlan format; no historical version0/2 format or compatibility claim is invented. There are no production transformation steps yet. Existing source/schema/accepted fixtures and the canonical integer-mm semantic rules remain unchanged.

`parseProject` performs bounded JSON admission through `MigrationRegistry(1, validateProject, [])`. Current canonical projects preserve exact content and IDs; future positive safe-integer versions return a `future-version` error saying **Update the app to open this newer project**. Missing/fractional/zero versions fail. Unknown fields and invalid geometry are rejected rather than dropped/rounded. The public current-success result remains `{ok:true,document}`. UI file import and its detailed version-error presentation belong to PH1-T04; current saved-recovery inspection can still show a general unsupported-data warning.

The registry first admits plain JSON values (plain/null-prototype objects and ordinary dense arrays). Date/class instances, array subclasses, holes/decorations, symbol/hidden/accessor properties, undefined/bigint/nonfinite values and cycles reject before serialization. Accessors are not executed. A depth-64 and bounded-node-work guard precedes the existing 10 MiB serialized-size cap, preventing silent flattening inside migrations without changing the general serializer contract.

The pure generic registry supports only reviewed adjacent steps (`from→from+1`). Each descriptor requires an input validator, transform and output validator; the final latest validator always runs. Duplicate/skip/backward/out-of-range descriptors and an invalid latest validator reject configuration. The registry snapshots the five explicit fields, including prototype-defined callbacks, and freezes its configuration. Callbacks must be reviewed pure functions operating on their value argument and declared descriptor fields; bind a callback explicitly if it needs an instance context. Input data is JSON-copied before deep freezing, so caller-owned objects are never frozen or mutated. Callback exceptions, invalid output versions, non-JSON/deep/cyclic/oversize outputs and missing chains return failure. There is no storage write in the runner.

Successful output includes a new owned value, source/target versions, applied target-version list and canonical JSON. Canonicalization retains the existing sorted-key, finite-JSON, depth 64 and 10 MiB rules. Determinism is a requirement for reviewed transforms; a static registry cannot prove that arbitrary trusted callbacks never use time/randomness/side effects. Hashing, local transaction CAS and native durability remain in persistence, not migrations.

Future real schema changes must preserve the actual previous schema/generated validator and input fixtures, add a pure `vN_to_vN+1` step with exact independent input/output golden expectations, validate every boundary and update the current schema/type/constant together. Add roundtrip/edit/undo/persistence/render tests before allowing latest-version writes. Migration failure must preserve the original file and live drawing; an explicit recovery copy is a separate operation. Historical support is advertised only after real fixtures pass. The synthetic 1→2→3 schemas in `migrations.test.ts` test the framework only; they are never used by production parsing or saved as projects.
