# D37 — renderer resources and recovery (PH3-T04)

2026-10-14, Codex under D17 and D36. General renderer correctness and Linux/debug verification only; no cloud, mobile tuning, sharing, physical-phone, billing, security/privacy, release or Claude work.

- ResourcePool leases own their entry, rather than a reusable key. Identical keys share until the last lease releases; release and close are idempotent. Close invalidates outstanding leases and attempts every entry even if one disposer throws. Failed factories are not cached; successful disposals and disposal failures have separate counters, so a throwing disposer cannot be counted as proven release. Factories clean partial allocations before registering them.
- SceneAdapter owns structural/batch geometry, canonical/neutral materials, furniture primitives and instance buffers. Replacement/removal releases the relevant leases; retained meshes keep ownership. Any unexpected apply failure closes the adapter and hides its partial scene. A fresh view creates a fresh adapter; no mixed scene is acknowledged as current. The unit cube creates its BufferGeometry owner before allocating attributes; analytical area/volume/winding properties accompany its rollback tests.
- Three r186 uses a module-global DFG lighting LUT. Each WebGLTextures owner registers a disposal listener on it; renderer.dispose alone leaves these listeners. The supported Material.onBeforeCompile uniform object reveals the assigned LUT after a draw. ShaderTextures leases that texture per renderer and disposes it before renderer properties are discarded, when the last renderer closes. It ignores canonical material maps. No private module imports or vendor modifications. The current app has one renderer; simultaneous renderers retain an earlier context's LUT listener until the final shared owner closes, so long-lived multi-renderer churn needs a separate design/test before adding that feature.
- Renderer teardown runs in useLayoutEffect before React detaches the canvas. OrbitControls r186 disconnect removes keyboard listeners from canvas.getRootNode(); passive-effect cleanup after detachment targets the wrong root. Independent document keyboard-listener and heap/resource checks cover this failure. Every independent cleanup step runs even if an earlier disposer throws.
- Context loss immediately clears current-generation/draw-call acknowledgment and blocks camera restoration/screenshots. A single monotonic3000msdeadline starts at loss; a draw after that deadline is rejected even if a busy main thread has delayed the timeout callback; repeated loss or a restored event cannot extend it. Only a successful draw of the latest accepted canonical generation ends recovery. Context and worker state are separate: an intact previous scene remains labelled stale after restoration and never emits current metrics.
- An initially unsupported WebGL device keeps its established explanatory panel with an explicit2Dbutton and no live renderer/API. Unexpected apply/render/other initialization/restore failure, or expiry, closes worker/RAF/timer/listeners/GPU owners and returns the existing ProjectStore to 2D. Drawing, autosave, Undo/Redo and full JSON remain available. A persistent localized notice explains recovery failure. A user can explicitly reopen 3D. Late callbacks cannot publish into the closed view.
- Guarded transient camera vectors use1e-12metre resolution to prevent sub-ULP drift across disposal/recreation; canonical geometry remains integer millimetres and is unchanged.
- Linux renderer-toggle cycles are not full project-open/close, native/device-memory or physical-phone evidence. renderer.info measures counts, not whole GPU bytes. CDP heap readings cover main-frame V8 only; workers, native/browser/driver memory and real-device gates remain separate. The fixed protocol records6/16/26-cycle warmup readings, establishes a36-cycle baseline, then measures50additional cycles with the unchanged≤10%V8 threshold. Six-cycle first runs exceeded that threshold; snapshots showed JIT growth plus the corrected document-listener root. Warmup/measurement details and initial failures belong in verification; they do not establish cold-start/device memory acceptance.
