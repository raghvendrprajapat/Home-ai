# D47 — structural CPU geometry and material bindings (PH4-T04 stage A)

2026-10-16 · Codex under D17, subject to D36. This is a renderer foundation; visible wall-side painting/palette and GPU-buffer reuse follow separate PH4-T04 stages. It does not complete FR-022/SYNC-005 or claim a200ms/physical-phone target.

Each derived mesh now has stable materialRanges: contiguous triangle ranges labelled left/right/floor/threshold/ceiling, independent of current material IDs. These are transient worker/renderer metadata, not canonical project entities or a schema migration. Wall orientation/cap assignment stays identical to the prior renderer: left/right are relative to wall.a→wall.b and nonlongitudinal caps use its prior left-side rule. Room floors, zero-sill door thresholds and fixed white ceilings keep the previous material-selection semantics.

Geometry dependencies contain actual side/floor UV scales rather than their binding IDs; the conservative full material UV table remains. Endpoint/topology, dimensions, openings, floor elevations, ceiling heights and UV changes still trigger authoritative structural analysis. Binding changes remain in advisory dirty wall/room/threshold sets. A binding key tracks wall side IDs, room floor IDs/order and first-material fallback; unrelated metadata/colour/roughness edits retain the exact previous mesh array.

For a same-scale paint binding, CachedSceneBuilder skips solid union/triangulation, resolves stable ranges to current IDs and rebuilds only small draw-group descriptors, coalescing contiguous equal IDs. Position/normal/UV/range buffers are reused by reference. Earlier bundles/groups remain unchanged; a later real geometry edit also rebinds unchanged per-mesh cache entries to the latest materials. Actual UV changes retain their existing rebuild path. Complete surface/shared-edge dependency signatures remain authoritative; no geometric predicate or accepted fixture changes.

Derived range admission rejects missing/unknown/non-owned slots, gaps, bad triangle counts and incomplete coverage. Lookup uses own properties, not prototype values. The canonical command/model validation still owns real project validity; renderer metadata never writes the model.

Tests include analytic left/right/cap expectations after splitting a formerly all-white merged group; exact command/Undo/Redo and invalid material rejection; two rooms with both living-hosted thresholds; unchanged neighboring floors/ceilings; UV rebuild necessity; later remote geometry edits; malformed range/slot coverage; and100seeded random paint sequences compared with fresh derivation. An isolated comparison against pre-foundation renderer code checks all positions/normals/UV/groups/bounds/volume/stats across9corpora, including reversed host, different paint, floor finishes, custom UV, no openings, raised floor and unequal ceilings. This is Codex verification, not Claude-authored fixtures or proof of every drawing/GPU.

Important limitation: SceneAdapter still rebuilds GPU geometry when material bindings/groups change, and existing2D fills are not yet a complete material display. Stage A proves CPU-buffer reuse only; GPU rebinding and visible per-side/floor palette follow. Textures/KTX2, furniture variants and delivery infrastructure are not added. No new dependency/schema/immutable asset/owner-input change. D36 accounts/cloud/history/mobileoptimization/sharing/realphone/billing/security/privacy/release/finalClaude scopes remain unstarted. Ordinary Linux/browser/Android debug checks are validation only.
